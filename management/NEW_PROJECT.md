# 新项目启动（约 10–20 分钟，不含数据处理与软件安装）

## 1. 建立项目身份

将模板解压到新项目目录，保留扁平布局。读取 AGENTS.md 和 project.json；填写项目名称、研究问题、负责人、当前阶段。检查是否实际存在 Git 仓库；解压副本可能没有 .git，不能仅凭目录名称声称已经版本控制。需要时在新项目初始化 Git，先检查忽略规则与敏感文件。

模板附带的合成示例、登记占位项和复现导出配置都不是新项目成果。将模板历史明确标为参考；新建本项目 STATUS、首张任务卡和项目登记，正式任务接入前保持 formal.enabled=false；更新导出配置，不能沿用合成分析版本冒充真实结果。

## 2. 写清研究对象和第一项交付

在 SPECIFICATIONS.csv 填分析单位、处理/对照、Y/X、时间、样本、变换顺序、固定效应、聚类与识别限制；未确定项明确待定。结构项目另记录假设、方程、参数、求解及验收标准。

在 DATA_REGISTRY.csv 登记首个输入的来源、版本、键、权限和缺失规则。复制 templates/TASK.md 到 management/tasks/，只定义第一项可验收交付；不要一次填满未来所有任务。

## 3. 配置执行环境

从 config/machine.*.example.json 创建本机配置，填写 Stata 与三层数据路径。核对 Stata/ado 依赖。首次环境验证可运行 README 的合成 demo；它仅验证示例流程。真实清洗/估计须单独接入 config/tasks.json 并明确输入、产物和 QA。服务器默认关闭，沿用单次同步授权规则。

## 4. 选择协作方式

阅读 AGENT_WORKFLOW.md。简单任务单 agent；适合拆分时由协调者按任务卡分配文件所有权。优先试点“一张回归表逐列核查”：执行者整理证据，审查者独立核对，协调者汇总。角色规则不等于已启动子 agent，平台不支持时串行执行。

## 5. 验收与交接

按任务卡验证实际产物，再更新 STATUS 和相关登记。论文关键论断登记 CLAIMS.csv；重要决定写恢复卡。没有结果时明确未运行，历史模板 PASS 不作当前证据。

以后续聊直接使用 ai_records/START_HERE.txt；首次启动可复制 ai_records/NEW_PROJECT.txt。

首次配置输出时读取 OUTPUT_LAYOUT.md，明确日志、研究表格与图片的独立路径。
