# 任务与多 agent 协作规范

状态：规则与人工/agent 执行模板已提供；不是后台调度服务。规则入口为根目录 AGENTS.md。

## 1. 先形成一个可验收任务

较大任务复制 management/templates/TASK.md 到 management/tasks/<task_id>.md；小型解释和单文件修订无需填表。已有任务优先续用。协调者将当前任务链接写入 STATUS.md，不额外维护一份重复任务列表。

任务卡记录目标、优先级、明确交付物、输入及代码版本、依赖、文件所有权、验收标准、预计时间与实际耗时。开始前明确授权范围；已授权范围内持续完成，不逐步重复询问。研究规格待决定时，继续无依赖的工作，暂停依赖该决定的步骤。

状态使用 READY / RUNNING / REVIEW / DONE / BLOCKED。缺输入、授权或关键研究决定记 BLOCKED，并写明解除条件；耗时长不等于阻碍。DONE 必须有适用验收证据；文档任务的静态检查不能写成回归通过。

## 2. 按需分工，不常驻完整团队

用户授权执行任务后，本项目允许协调者对边界清晰、能够独立验收的子任务按需委派子 agent；简单任务默认单 agent。平台/上级限制优先；不能委派时串行执行并如实标明。此规则不授权创建新的用户聊天、跨聊天发消息或设置提醒。

默认一个协调者，最多两个工作子 agent 同时工作；角色可按阶段复用。只有预期收益高于交接成本时并行，任务卡记录理由和时间/调用预算。不要为凑角色重复阅读全部项目。

|角色|输入与责任|写入范围与交付|
|---|---|---|
|协调者|确认需求、依赖、任务分工，综合证据|唯一维护 STATUS、DECISIONS、任务总状态、登记表与恢复索引|
|执行者|按固定数据版本和已确认规格实现|仅修改认领的代码或数据生产任务；交付产物、日志和差异|
|审查者|先根据原始任务及规格形成检查项，再核对产物|对生产代码、数据与稿件只读；仅写指定审查报告，不给自己实施的结果作独立审查|
|文献/写作者|按任务选择文献核验或基于已验收结果写作|仅修改指定报告/稿件；文献指向原文，数字指向结果证据，不自行重估|

每次委派须包含目标、必读文件、输入版本、允许写入路径、禁止事项、交付物、验收条件。明确告知各执行者共享工作区，不得撤销别人的修改。子 agent 返回证据，由协调者统一写共享登记表。

同一文件或可变数据目录同时只能有一个写入者；在任务卡认领后启动。长任务从确定代码快照执行；版本化数据只读共享、输出目录各自唯一。跨聊天手工认领不是系统锁，尚不能保证原子互斥；无可靠隔离时，重叠写入必须串行。独立代码分支可使用隔离工作区，大型数据不随之反复复制。

并行示例：核查文献定义与审查已有规格；读取相同冻结数据的互不覆盖分析。串行依赖：数据验收→估计→结果审查→正式写作。不要在分析数据尚未通过时据此提前写结果。多个 Stata 进程还须核对内存、许可和处理器预算，不因 agent 并行自动并发回归。

## 3. 执行—审查—修订

执行者提交后，审查者使用 management/templates/REVIEW.md，问题须带位置、证据、影响及修复后验收方式。区分“已证实错误”“待研究判断”“可选改进”；无证据的疑虑不能宣称为错误。

默认最多两轮修订复核。已证实错误由执行者在授权范围修复；规格、样本或解释的实质改变交给 项目负责人 判断。两轮后未解决的问题留为开放项；不能为了停止循环标为通过，也不无限互相辩论。AI 评分和多数意见不能代替实际检查或识别论证。

实证最低检查：分析单位/键、处理对照、Y/X、变量时间和变换顺序、实际样本及缺失/零值、固定效应/聚类、估计器省略/不可估计状态、各列完整性、表文一致。数值容差事前确定。根据任务范围选择检查，未检查写 NOT_CHECKED，不填 PASS。

理论任务检查假设、约束、求导、单位和经济含义；数值结构任务另查参数恢复、收敛和均衡残差。复现成功与因果识别成立分别报告。

## 4. 状态、结果复用与结论追溯

运行状态以 run.json、退出状态、必需产物及适用 QA 为证据。STATUS 是协调者维护的简短摘要，发生冲突先检查真实文件。恢复卡只记录关键决定和证据，不复制所有聊天。

现有 run.py 尚无依赖调度、缓存、断点恢复、原子任务锁或自动状态面板。可以在获准范围显式复用已冻结输入，但必须核对生产来源、版本、适用代码/配置/环境与验收结果，记录复用理由。文件存在不是可复用证明；输入或筛选变化后下游结果标 STALE，重新验收。失败运行的部分产物不得自动升级为有效输入。

关键论文结论登记 management/CLAIMS.csv；表图来源继续用 EXHIBITS.csv。链条为：正文位置→exhibit/列→spec_id→run_id→估计与实际样本。记录单位、比较基准和适用样本；文献论断绑定来源与页码/节。结果或稿件变化后核对关联论断，数值复算与识别解释分别审查。论断状态为 DRAFT / VERIFIED / STALE / UNVERIFIED；VERIFIED 只代表登记的核验范围，不代表因果结论获证实。

## 5. 新项目与试点验收

先按 NEW_PROJECT.md 完成项目配置，再从一张回归表的逐列核查试点。记录总耗时、人工干预次数、返工轮次、有效问题和新增成本；没有可比较的单 agent 基线时不声称加速百分比。

未来能力按 AUTOMATION_ROADMAP.md 分阶段实现；未实现的命令不得写进执行入口。保留 Stata 生产链、逐列 reghdfe/outreg2、日志位置、不可覆盖版本与服务器授权规则。
